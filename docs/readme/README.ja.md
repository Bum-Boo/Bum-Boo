私は **AIエクスペリエンスデザイン** に取り組んでいます。AIを開発者向けツールの枠を越えて役立つものにしながら、その状態、範囲、結果を使う人が理解できるようにする実践です。

私の活動領域は、デザイン、認知、テクノロジー、メディア、日々の習慣を行き来します。デスクトップユーティリティ、エージェントのワークフロー、ローカルアーカイブ、コントローラー、小さなインターフェースはどれも、日常の体験を軽やかで力強いものにする手段になり得ます。

## ラボ

私は見過ごされやすい摩擦から始めることがよくあります。確認できない変更、手に負えなくなったフォルダー、言葉の壁、あるいはボタン一つで済むはずの反復作業です。

> **繰り返し立ち返る問い：** 人間の選択を消さずに、AIは人が自分の力をより感じられるよう手助けできるだろうか？

<img src="../../assets/research-os.svg" width="100%" alt="日常の摩擦から有用な変化へ進む研究プロセス" />

## 現在の研究テーマ

- 開発経験のない人のためのAIエクスペリエンスデザイン
- 認知、発達、学習、注意、そして道具が行動を変える仕組み
- 人間の判断を見える状態に保つ、書き込み前レビュー型エージェント
- プライベートで永続的かつ可逆的な作業のためのローカルファーストシステム
- 真剣なツールへの心理的な壁を下げる遊び心のあるインターフェース
- 特定の媒体や製品カテゴリーに縛られない学際的な実験

### 現在の仮説

- AIは、その状態、範囲、不確実性が見えるとき、より役立つものになります。
- 非開発者に必要なのは単純化された知能ではなく、より良いインタラクションの約束事です。
- 遊び心のあるインターフェースは、運用上の真剣さを隠さずに恐れを和らげられます。
- ローカルファーストのアーキテクチャは、プライバシー基盤であるだけでなく、体験設計の選択でもあります。

### 生産的な緊張関係

| 緊張関係 | 探究していること |
|---|---|
| 自動化 ↔ 主体性 | コントロールが見えなくなる前に、どこまで自動化すべきか？ |
| 知能 ↔ 読み解きやすさ | 強力なシステムでも、何をしているかを人間の尺度の言葉で説明できるか？ |
| 実用性 ↔ 喜び | 真剣なワークフローは、気を散らさずに楽しいものになれるか？ |
| 広がり ↔ 一貫性 | 開かれた探究から、焦点の合った有用な成果物をどう生み出すか？ |

### 未完の問い

- 会話が数ある素材の一つにすぎないAIインターフェースは、どのような姿になるか？
- 道具は努力を無差別に肩代わりせず、認知的な成長をどう支えられるか？
- 見過ごすほど小さく、それでも再設計する価値のある日常の不便とは何か？

## 制作に使う素材

Python、TypeScript、JavaScript、Node.js、Electron、PowerShell、GitHub Actions、Obsidian、Hermes Agent、MCP、ComfyUI。体験と制約に応じて選んでおり、ツールの一覧がこの実践のアイデンティティなのではありません。

## スタジオノート

下のパネルは公開リポジトリのデータから生成されます。スコア、連続記録、生産性の主張ではなく、小さな事実のスナップショットです。

## 制作原則

- **ローカルファースト。** 個人のワークフローデータは、その所有者の近くに保ちます。
- **書き込み前にレビュー。** 変更が永続化される前に見えるようにします。
- **可逆性を設計する。** 下書き、ブランチ、バックアップ、明確な出口を優先します。
- **開かれた研究。** 問いそのものに分野と媒体を選ばせます。
- **日常の喜び。** 真剣なテクノロジーも、遊び心があり人間的でいられます。
